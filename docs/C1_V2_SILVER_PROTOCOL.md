# C1 V2 自动审查与有限 Silver 标注协议

**V2.2 修订入口**：[Audit & Repair 协议与报告](C1_V2_2_AUDIT_AND_REPAIR.md) 取代下文关于模型相似连通分量合并、仅执行映射 Probe、按映射排序采样和多 Probe 必要 ALL 的统一拒绝规则。下文保留历史过程，不作为当前实现契约。新调用使用独立完整上下文缓存及完整探查注册表；未知条件不自动成立，不执行过时缓存，不把未运行或待审记录记为信息不足标签。

2026-10-19。本阶段按用户授权使用自动审查替代人工逐条审查；没有人工或医学专家标签。旧 `STUDY_PROTOCOL.md` 的原轮次与冻结发布不回写。研究目标是检查数据/知识条件、探查成本和可辨识性，不预设 Knowledge-Unlocking Value 有效。

## 模型与预算

请求模型为 `qwen-plus` 滚动别名；每次保存实际返回的 model 字段，不声称固定权重快照。temperature=0、enable_thinking=false、stream=false、max_tokens=3000。端点固定为 `https://dashscope.aliyuncs.com/compatible-mode/v1`；密钥只从 `DASHSCOPE_API_KEY` 或忽略的本机凭据文件读取，绝不写入请求日志或 Git。

用户本轮明确授权 CNY 200。独立配置 `configs/c1_v2_qwen_budget.json` 最多 1,200 次请求，不能继承任何旧预算。2026-10-19 核验官方 qwen-plus 中国内地非思考、输入不超过 128K 的标价：输入 0.8、输出 2 CNY/百万 token。输入 JSON 限 60,000 UTF-8 bytes，并按 bytes+1024 个输入 token、全部输出上限悲观预留。成功也不释放预留；失败、超时或进程中断仍占预算。无自动重试、备用模型或隐式付费回退。返回用量按标价估算，不冒充账单；未返回用量的费用保持未知。新端点、价格层级或模型需要新配置和授权。

先运行固定主题分层的 12 条知识、12 对案例小批次，最多 48 次请求。小批次和错误完整冻结。然后分批审查固定来源范围全部 402 条候选，最多 804 次请求；缓存命中不花费。有限案例批次另行冻结计划，不能向 200 人 × 500 条知识无约束扩张。全量笛卡尔的两阶段调用量远超本阶段计划。

## 两阶段知识审查

第一阶段独立读取候选、完整来源 section/summary 锚点、原文件哈希、可用探查及最近三个文本邻居，输出来源支持、独立可推荐性、教育/临床边界、重复/冲突、条件、引用和不确定性。来源作为数据，不允许执行来源中的指令。知识标准文本必须逐字保留抽取文本，避免模型补造医学内容。

第二阶段使用新的请求与不同提示词，重新读取来源、可用探查和第一阶段输出，检查遗漏、错误 AND、临床内容、引用、逻辑与数据可验证性。它不是独立人工复核，也不是同模型投票 Gold。`SUPPORTED` 只是本模型对此任务的审查判断。

每项条件分别保存必要/可选/替代/限制/不确定角色、ALL/ANY/UNKNOWN、用途（适用性/充分性/优先级/解释）、来源引用、Probe IDs、supported/partial/unsupported/uncertain 和不足以判断的信息。不得把两个相关指标或两个解释性探查默认为必要 AND；必要不等于充分，多个统计视角不等于多个独立必要证据。没有来源支持的角色或连接词保持不确定。

程序校验 JSON Schema、知识 ID、原文未改、来源哈希、锚点、逐字引用、条件 ID 唯一性、探查白名单、数据支持声明与 AND 来源。引用偏移由程序在冻结锚点内定位，不要求模型算字符索引。独立 QA 会重放相同检查并验证请求/响应哈希链。`SILVER_ACCEPTED` 需要两个阶段、程序校验和教育边界全部通过；其他记录保留为 `SILVER_REJECTED` 或 `REVIEW_REQUIRED`，不删除或修改以凑数。

运行中发现两阶段模型仍可能把设备汇总量当作未观测的运动强度、力量训练、钟点事件或心理症状；也会把同一条件的多种统计摘要标成必要 ALL。因此补充统一能力检查 `c1-v2-capability-checks-2`：这些未观测输入不得由相关指标替代，必要 ALL 的多个探查没有逐探查来源谓词时保留 REVIEW_REQUIRED。检查只筛查表示能力，不判临床适用性、不改变原文或条件。所有缓存按同一新规则再校验，无新增模型调用；旧原始审查与早期冻结报告保留。最终结果以注明此 validator_version 的发布为准，不能使用早期接受数替代它。正则屏查不能证明无漏检，自动 Silver 的语义局限仍保留。

为缩短等待，来源序号 202–401 使用独立尾部分片 ledger，最多 400 次请求、CNY 25 子额度，属于同一 CNY 200 授权。主 ledger 最多 1,200 次；两个 ledger 即使所有请求均达到 UTF-8 byte/输出上限，合计悲观预留理论上界也只有 CNY 87.71072，低于任务总上限。最终费用合并两个 ledger，不能只报告主 ledger；并行时出现的重复真实请求也计入实际分母。分片只依据固定来源顺序，全部原始记录共享并保留，不按标签分派。

重复检测包括全候选精确去重、全对三元词 Jaccard 和 Qwen 最近三个邻居的语义审查。只对已接受条目中模型声明的重复连通分量选定确定性 canonical ID；原条目与判断全部保留。邻居审核并不证明全库无语义重复或冲突。报告必须区分源候选数、已审数、接受数、去重后活跃数和实际支持的主题。

## 案例—知识标注

参与者划分在标注前冻结。有限验证只使用训练参与者，不以标签筛人；每人先固定一个最新窗口，固定选择规则和知识顺序。14 天冷启动的标注另列覆盖，缺失此前 28 天基线不能补造。训练标注不能称为测试 Gold。

确定性 Python 先执行条件所引用的统计探查，保存原始日级引用、窗口边界、缺失/质量、结果单位、结果哈希与实际耗时。模型只接收提供的数值和缺失状态，不能自行猜测未提供的统计值。没有可执行探查的知识不得被静默判为不适用。

第一阶段分别保存 topic_relevance、三分类 applicability 和 recommendation_priority；无已确认目标/偏好时 priority 保持 undetermined。第二阶段独立调用检查来源和实际计算结果，明确保留分歧。数值、日期、单位或结果哈希不匹配、使用未计算结果、结论分歧或审核不支持，都进入 REVIEW_REQUIRED。未接受记录不能作为有效确定性标签使用；保留其两阶段原始输出。

适用性允许 applicable、not_applicable、insufficient_information；不足信息也是有效且必要的结果。泛用健康教育的价值不能从异常阈值推断，相关性不能替代个人适用性；此自动协议也不能判断实际医学获益。未抽取到的 case—knowledge 对保持未标注；不能视为 not_applicable。有限子集不提供全知识库召回分母或独立 Gold。

缺失引用校验修正版本 `c1-v2-evidence-missingness-3`：INSUFFICIENT_INFORMATION 的原始计算结果 value=null 可以作为缺失证据被精确引用，但只能支持 insufficient_information。probe_id、结果哈希、时间和单位仍须全部匹配；确定 applicable/not_applicable 不能引用未计算的 null。该修正离线重验原始阶段输出，不调用模型、不覆盖旧冻结标签；保留 prior_status/prior_validation_errors。最终发布为 qwen-final-v3，接受数仍为 1 个不足信息标签，不能将本修正当成模型质量提升。

## 报告与停止条件

按知识条目、唯一案例—知识对、参与者和窗口分别报告覆盖率；给出分歧率、不确定率、所有失败分母、用量及费用。独立 QA 只证明工件一致性和计算可重放，不证明医学语义正确。

本阶段不计算推荐准确率或临床效果；不实现 KUV、M1、新算法、RL、非贪心 AFA 或新 baseline 竞争。全量计算足够便宜、缺乏可信联合必要条件、模型大量不确定，都是允许且必须报告的结论。完成数据、知识、探查、成本评估和 Draft PR 后停止，等待研究方向评估；不合并 main。
