## Qwen 传输和 Evidence ID 修复

新实时客户端为 `src/day1/client.py`，采用恰好一个具名声明式函数的入参输出；动态 Schema 把 query、knowledge、condition 和 evidence ID 限制到当前合法集合。模型只返回选择及判断；数值、单位、窗口、来源和计算哈希由 Provider 绑定。没有执行模型生成的工具或代码。

采用具名 `tool_choice`，没有使用 Qwen 暂不保证的 `required`；调用方式依据 [官方 Function Calling 文档](https://help.aliyun.com/zh/model-studio/qwen-function-calling)。新的模型档位和快照别名依据 [官方 Qwen3.8-Max 页面](https://help.aliyun.com/zh/model-studio/qwen3-8-max)，本轮核验北京标准输入/输出价格为 12/36 元每百万 tokens，未假设折扣。

以下检查已实现并离线验证：

- 必须恰好一个预期函数，拒绝截断、混合自由文本、错误函数、重复 JSON 键和非有限数值。
- 合法 ID 若指向错误 Probe、错误状态或错误测量含义，仍属实质性失败。
- 新鲜独立 ledger；调用前占用保守预算，失败或不确定请求不自动重试。
- 原始响应先写入再解析，失败响应及预留费用保留；缓存重放检查原请求文件及双向哈希。
- 记录请求模型与真实返回模型；仅接受预先声明的别名/快照，不能改写模型身份。
- ID 烟测授权不能用于适用性标注；当前新授权额度和请求数仍为零。

全套测试 **145/145 通过**，日志为 `local/day1/tests-round2-final.log`。新增测试发现并修复 Schema 构造器的共享对象问题：深拷贝仍保留字段间别名，动态 enum 会污染其他字段；现已消除共享后再约束 ID。首次错误和审查 ID 前缀录入错误均保存在新的失败记录中，没有修改历史通过/失败记录。

这仍是工程修复与真实接口格式的离线验证；**未付费调用前不能声称真实 Qwen 链路已经通过**。
